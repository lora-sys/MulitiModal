# 生理数据采集与训练准入协议 V1

**版本**：`physio-collection-v1-draft`，2026-11-11  
**实施对象**：下一批真实受试者的按摩前、过程中、结束后采集。  
**当前状态**：待设备字段确认和实验负责人批准后生效，不能追溯认定历史记录合规。  
**关联**：#24、#26、#96、#102、#107，`docs/design/physio-real-data-v1.md`，`src/physio/schema.py`。

## 1. 研究问题与边界

同时保留三个**独立任务**，不混用标签：

| 任务 | 预测时点 | 可用输入 | 目标 | 当前研究状态 |
| --- | --- | --- | --- | --- |
| 按摩前疲劳状态 | Pre 结束 | Pre 的身体与生理观测、时间上可得的上下文 | 独立疲劳自评分数 | 尚无独立标签 |
| 按摩后疲劳变化 | 按摩开始前 | Pre 观测和**实际确定**的按摩方案 | Post 自评减 Pre 自评 | 尚无独立标签、协议上下文不全 |
| 按摩中状态 | 每个实时窗口截止 t | 静态 Pre 和 t 时刻及之前的真实观测 | 待校准的当前状态 | 尚无可信实时标签 |

`vendor_fatigue`、`vendor_health` 及其差值属于 **VENDOR_PROXY**。BPSI/EFRI 属于 **DERIVED_EXPERIMENTAL**。任何一类都不能替代独立疲劳量表或证明按摩疗效。收缩压、心率等变化是**生理响应**，没有证据不得一律定义为疲劳改善。

## 2. 身份与 Session 定义

1. 每位受试者使用独立的设备账户 `memberId`，并生成独立的、随机的 `subject_id`。研究侧保留受试者与账号的受控映射；建模数据只用不含个人身份信息的随机标识。
2. 一次实际按摩分配唯一 `session_id`，同一受试者的两次 Session 不得重叠。禁止依据「同一账号相邻两条血压」单独证明按摩场次；优先用设备按摩开始与结束事件、受试者和操作员确认。
3. 每条传感器记录保留 `source_record_id`、`source_type`、`device_id`、`measured_at`、`received_at`、`phase`、`raw_value`、`unit`、`quality`。带时区的事件时间为配对依据，上传时间仅作延迟审计。
4. 任何设备或同一模态的同一原始记录不能同时担任 Pre 和 Post。合并快照与完成态时，**每个指标**都要保存真实的来源记录 ID，而不是只保存端点组锚 ID。
5. 历史统一账号记录必须继续标记 `SHARED_ACCOUNT_UNKNOWN`。不因为人工补写 `subject_key`、性别或修改哈希，就把这些记录认定为跨受试者可验证数据。

## 3. 建议冻结的实际采集流程

以下为第一轮预实验的**操作规范建议**，不是论文提供的医疗阈值。设备无法实现时应记录偏离，不允许补造。

| 阶段 | 执行动作 | 必须记录 |
| --- | --- | --- |
| 受试者登记 | 知情同意、随机身份、设备账号核对、基本信息 | `subject_id`、`memberId` 映射、同意状态 |
| Pre 准备 | 使用同一测量位置与姿势，建议安静休息 5 分钟后测量 | 休息起止时间、姿势、设备、环境备注 |
| Pre 采集 | 询问疲劳自评 0 至 10 分，记录血压、心率、血氧、可获得的其他测量与舌面检查 | 每条测量原始记录 ID、时间、单位、质量 |
| 按摩开始 | 确认已选择且实际启动的按摩程序，不允许事后推测 | `protocol_id`、程序 ID、强度、计划时长、开始事件 |
| During 采集 | 若设备能稳定提供 EEG 或其他信号，逐点记录并校验时间戳 | 采样率、信号质量、设备掉线、程序调整事件 |
| 按摩结束 | 记录实际停止时间、停止原因、实际程序及强度变化 | 结束事件、实际时长、异常 |
| Post 采集 | 在结束后固定时间窗口内重复疲劳自评与对应生理测量，建议先以 0 至 5 分钟作为试验配置 | 与 Pre 同量表、同单位、实际测量时间及姿势 |
| 数据核查 | 比对端点、完整性与原始记录，不符的 Session 隔离 | 逐字段掩码、缺失原因、QC、协议偏离 |

**主观疲劳条目**：`你现在感觉有多疲劳？0 表示完全不疲劳，10 表示极度疲劳。` 采用 0 至 10 整数。此单条问题是第一轮预实验的操作性参考，不等于完整的经验证疲劳量表。若采用 KSS 或其他正式量表，须记录准确的量表名称、版本、题目与使用限制，不得将困倦直接改称疲劳。

预实验可以同时记录近一晚睡眠时长、当前是否刚刚运动、咖啡因摄入时间、测量环境温度等可能影响疲劳的背景因素，但若未实际采集，不可创建伪观测值。

## 4. 必需记录字典

| 字段 | 来源 | 阶段 | 训练使用 |
| --- | --- | --- | --- |
| `subject_id`, `session_id`, `memberId` | 登记与设备 | 全程 | 分组/QC，不作生理特征 |
| `measured_at`, `received_at`, `phase`, `source_record_id` | 原始事件 | 每次测量 | 配对与质量审计 |
| `protocol_id`, `program_id`, `intensity`, `started_at`, `ended_at` | 设备与操作记录 | During | 已知时方可作程序效应预测输入 |
| `fatigue_self_report_pre` | 人工独立问答 | Pre | 独立候选参考标签 |
| `fatigue_self_report_post` | 人工独立问答 | Post | 独立候选变化目标，仅训练 |
| `hr`, `spo2`, `sbp`, `dbp` 及真实可用指标 | 设备测量 | Pre/Post | Pre 特征及差值，保留原始单位 |
| `eeg` 原始信号或设备汇总 | 设备，如确实可得 | During | 单独任务特征或研究标签，不得泄漏到 Pre-only |
| `vendor_fatigue`, `vendor_health` | 厂商算法输出 | Pre/Post | 厂商代理标签，不能视为独立参考 |
| `observed_mask`, `valid_mask`, `imputed_mask`, `label_masks` | 处理系统 | 派生 | 分别判定，不得混用 |
| `label_version`, `pipeline_version`, `protocol_version` | 研究系统 | 派生 | 可复现与审核 |

设备无法提供的字段要标为 `NOT_AVAILABLE`，而不是自行猜测程序或设备输出。当前历史 `protocol_version=UNRECORDED` 应保持原样。

## 5. 逐字段准入规则

| 数据类别 | 可进入工程测试 | 可作独立疲劳监督 | 处理方式 |
| --- | --- | --- | --- |
| 真实且质量合格的 Pre 特征 | 是 | 不直接当作疲劳真值 | `observed=True`, `valid=True` |
| 当前训练折计算的缺失插补特征 | 满足特征规则时可 | 否 | `observed=False`, `imputed=True`，保存插补器 |
| 历史外部性别均值补齐 | 只能按未观测处理 | 否 | 保留旧值供对账，模型侧标记缺失并不得拟合作为实测 |
| 同一记录被当作 Pre/Post | 否 | 否 | 差值 `None`，掩码 `False` |
| 端点组重叠、Session 重叠、跨 Session 重复记录 | 按 QC 决定 | 否 | 端点组重叠只拒绝相应模态的差值；跨 Session 重复或同人窗口重叠拒绝整场标签，记录原因 |
| 实测 Post 减实测 Pre 的血压、心率等 | 可作生理响应工程标签 | 否 | 必须符合时间、单位、原始来源和异常值 QC |
| 实测 Post 减实测 Pre 的厂商疲劳分 | 仅可作 `VENDOR_PROXY` 工程标签 | 否 | 不准换名为「真实疲劳改善」 |
| 两次独立疲劳自评 | 待协议、身份、量表审查 | 候选，可在审查通过后使用 | 保留原题、评分、时间和测量者 |
| 缺少合法测量的 `y_pri` / EFRI | 否 | 否 | `None` / `ABSTAIN`，绝不补零 |

**折内处理要求**：受试者先分折，再在每个训练折拟合插补值、标准化器、权重和特征选择。验证与测试折只使用该训练折的参数。同一受试者全部 Session 属于同一折。物理受试者身份未验证时，跨人泛化不可宣称。

## 6. 版本、实现和验收

- 仓库里已有 `src/physio/dataset.py` 的受试者分折、`FoldImputer`、`admit_delta_targets` 和 `src/physio/real_export.py` 的端点重建。重复规则优先修补这些模块，不创建新训练平台。
- `src/physio/admission_report.py` 提供逐字段训练准入审计视图。它区分 `OBSERVED_PHYSIO_DELTA`、`VENDOR_PROXY_DELTA` 与 `UNAVAILABLE`，但不会修改任何正式 GO 门禁。
- `GO_ENGINEERING` 仍按现有合成工程验收独立判定。`GO_REAL_DATA_TRAINING` 与 `GO_RESEARCH_CLAIMS` 当前均为 `NOT_GRANTED`。
- 每次正式导入输出 Session 数、独立身份数、各类缺失、重复或重叠端点数、按字段统计的有效标签数、被拒绝原因和版本哈希，不以 `COMPLETE` 一项决定所有任务资格。
- 测试覆盖一次记录充当两端点、前后时间倒置、长间隔、单侧缺失、补值作为标签、跨 Session 复用记录、同一受试者的重叠 Session、厂商代理误作独立真值、训练折外插补泄漏。
- **上线条件**：先用新的独立账号采集一批可核查数据，并由负责人确认设备字段字典及协议；再另行审批训练目标与评估协议。本次代码修复不会自动解锁真实数据训练。
