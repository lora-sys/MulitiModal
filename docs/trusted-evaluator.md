# 独立可信评价环境：部署契约与安全架构

在严肃科研与生产级模型认证场景中，必须部署完全独立于 Agent 执行环境的外部受信评价服务（Trusted Evaluator Service）。本文档定义该服务的安全边界、加密签名协议与部署契约。

---

## 1. 威胁模型与物理隔离要求

1. **不可信的提案环境**：Coding Agent 以及负责运行候选代码的执行环境被假定为“不可信主体”。Agent 即使拥有本地最高权限（如本地 root 或 Docker 管理员权限），也绝对无法访问或影响可信评价服务。
2. **硬件级/宿主机级物理隔离**：可信评价环境必须部署在研究者单独控制的独立物理机、安全受控私有云 VPC 或物理隔离的虚拟机上。在同一台宿主机上仅划分不同用户组或轻量命名空间**不满足**安全隔离标准。
3. **读写权限单向阻断**：
   - 评价服务私钥、真实测试集真值标签（Ground Truth）及评价计算逻辑驻留于受信主机内，对 Agent 严格不可见、不可写；
   - Agent 仅能通过单向安全 RPC / API 提交候选源码文件及其 Git Commit 标识；
   - 候选执行环境必须在网络断开（Network-isolated）且仅挂载无标签输入样本的沙箱容器中运行。

---

## 2. 验签闭环与证据血统绑定

每次外部受信评估完成后，服务端产出由不可伪造私钥签名的凭据（Signed Attestation Report），其内容严格绑定以下关键元数据：
- **候选代码指纹**：候选源码文件的 sha256 校验和及其 Git Commit SHA；
- **评估环境指纹**：受信沙箱容器镜像的 Digest、Python 运行时及评价器源码 sha256；
- **数据集血统**：数据集版本、划分清单 sha256 以及参考标准版本；
- **执行与评分参数**：随机种子、算力预算上限、实际执行耗时、多折外挂计算的主指标及逐维明细；
- **密码学签名**：使用非对称算法（如 Ed25519）对上述元数据摘要进行私钥签名。

> [!IMPORTANT]
> 任何下游系统在消费评估结论或晋级 Champion 时，必须使用研究者通过可信通道预先分发的公开公钥进行验签。凡验签失败、指纹不匹配或协议摘要不一致者，一律强制拒绝晋级。

---

## 3. 本地环境与可信环境现状差异

- **当前本地开发状态**：本项目当前的本地探索运行于开发机临时目录下，依靠 Python 子进程与局部文件隔离推进。此种方式不构成严格的容器或网络沙箱，评价隔离级别归类为 `AGENT_ISOLATION_UNVERIFIED`。
- **本地记录属性**：本地生成的 `runs/<tag>/results.tsv` 属于本地可读写的演进流水，其证据级别严格标记为 `LOCAL_EXPERIMENTAL`，严禁直接充当免检可信评估报告。
- **演进路线**：当科研模型通过本地充分验证并准备进行正式科研声称（`GO_RESEARCH_CLAIMS`）时，必须将候选代码整体提交至上述独立可信环境进行最终签发。
