# 独立评价环境：最小部署契约

真实研究需要由研究者控制一台独立的 Linux 机器或虚拟机。提案 Agent 及其 Docker 管理权限不能控制该机器、宿主机、评价代码、数据或签名密钥；同宿主机上另建账号不满足这一条件。

研究者在可信环境固定任务评价代码、数据与划分、容器镜像摘要、预算、晋级规则和签名公钥，并记录对应协议摘要。Agent 只提交候选源码和候选 commit 标识；服务端验证请求大小和格式，在隔离容器中运行候选，自己计算指标，保存结果并签名。候选输入不包含参考标签。Agent 和监控可读取签名结果，但不能写评价代码、数据、密钥或服务端结果目录。研究者从可信渠道分发公钥并独立保存协议摘要。

每份结果至少绑定候选源码哈希、commit、任务和协议摘要、评价代码及数据版本、镜像摘要、预算、种子、分数或失败状态。消费方必须验签、核对可信公钥与协议、候选提交和摘要；验签失败或不匹配时拒绝晋级。签名只证明结果来自持钥服务，不能单独证明评价协议合理或主机未被攻陷。

服务端必须限制每次任务的资源和时间，由独立于评价进程的受信主管理容器生命周期；主机重启、Docker 不可用、超时及重复请求的行为需要实测。权限检查应包括 Agent 尝试修改评价代码、读取参考标签与私钥、伪造和重放结果、以及候选进程尝试网络访问。失败状态不能计分或晋级。

当前仓库没有该服务或签名结果通道。现有本地 `results.tsv` 只是可写的实验记录。用户 systemd 定时器只覆盖同用户管理器正常运行时的进程意外终止，不能替代受信主机上的生命周期管理。真实入口继续拒绝运行，直到上述边界在目标环境中部署并完成正反例验证。
